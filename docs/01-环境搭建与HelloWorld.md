# 第 01 章　环境搭建与 Hello World

> **本章目标**：让一行 C++ 代码在你自己的电脑上跑起来。
> 这一章不需要理解任何算法，只需要**照着做**。
> 如果卡住了，直接跳到最后一节「报错急救包」。

---

## 1.1　先搞清楚：写 C++ 到底在干什么

你写的文件叫 **源代码**（`main.cpp`），是人能看懂的文字。
但 CPU 只认识 0 和 1。

中间需要一个**翻译**，把源代码翻译成 CPU 能执行的程序（`.exe`）。
这个翻译叫 **编译器**（compiler）。

```
 你写的             编译器               电脑能跑的
 main.cpp   ──►   g++（翻译）   ──►    main.exe
（人能看懂）                          （CPU 能执行）
```

所以写 C++ 只需要准备两样东西：

| 需要什么 | 干什么用 | 我们要装的 |
|---|---|---|
| **编译器** | 把 `.cpp` 翻译成 `.exe` | MinGW-w64（里面含 `g++`） |
| **编辑器** | 打字、写代码 | VS Code |

> 💡 你也可以用「记事本 + 命令行」写，但没有人那么干。
> VS Code 可以高亮语法、自动补全、一键编译、断点调试。

## 1.2　安装编译器（Windows）

### 步骤 1：下载 MinGW-w64

打开 <https://www.mingw-w64.org/downloads/>，
选择带 **UCRT** 运行时的版本（性能好、对 C++17 支持完整）。

下载到的通常是一个压缩包，例如 `mingw64.7z` 或 `.zip`。

### 步骤 2：解压到 `C:\mingw64`

**注意**：路径**不要有空格、不要有中文**！
`C:\Program Files\...` 这种路径有时会让编译器找不到头文件。

解压后应该能看到这样的结构：

```
C:\mingw64\
    └── bin\
         ├── g++.exe     ← 编译器
         ├── gcc.exe
         ├── gdb.exe     ← 调试器
         └── ...
```

> ⚠️ 如果你的压缩包解开后是 `C:\mingw64\mingw64\bin`，
> 说明**多套了一层**，把里层的内容移到 `C:\mingw64` 下。

### 步骤 3：把 `bin` 目录加进环境变量 Path

1. 按 `Win` 键，搜索「环境变量」，打开「编辑系统环境变量」
2. 点「环境变量」
3. 在**系统变量**里找到 `Path`，双击 → 「新建」
4. 填入 `C:\mingw64\bin` → 一路确定

**为什么要做这一步？**
这样你在任何目录敲 `g++`，系统都知道去哪找它。
不加的话，每次都得写完整路径 `C:\mingw64\bin\g++.exe`，很烦。

### 步骤 4：验证

**关掉所有已打开的终端**（环境变量只在**新开的**终端里生效），
重新打开 PowerShell，输入：

```powershell
g++ --version
```

看到类似输出就成功了：

```
g++.exe (MinGW-W64 x86_64-ucrt-posix-seh, built by Brecht Sanders) 15.2.0
```

如果提示 `'g++' 不是内部或外部命令`，见 [1.8 报错急救包](#18报错急救包)。

## 1.4　你的第一个程序

新建一个文件夹（比如 `D:\algo`），在里面新建文件 `main.cpp`，
把下面这段**一字不差**地敲进去：

```cpp
#include <iostream>
using namespace std;

int main() {
    cout << "Hello, World!" << endl;
    return 0;
}
```

### 逐行拆解（重点）

```cpp
#include <iostream>
```
**引入头文件**。`iostream` = input/output stream（输入输出流）。
没有它，`cin` 和 `cout` 都不认识。

```cpp
using namespace std;
```
**使用标准命名空间**。C++ 的标准库都放在 `std` 这个「箱子」里，
不写这行，你就得写成 `std::cout`、`std::endl`，很啰嗦。
竞赛代码**都写**这一行。

```cpp
int main() { ... }
```
**主函数**。整个程序**从这里开始执行**，而且**必须有且只有一个**。
`int` 表示它返回一个整数。

```cpp
    cout << "Hello, World!" << endl;
```
`cout` = character output，往屏幕输出。`<<` 是**流插入运算符**，
可以理解成「把右边的东西塞进输出流」。

```cpp
    endl
```
换行（end line），相当于回车。

```cpp
    return 0;
```
返回 0 给操作系统，**约定 0 表示程序正常结束**。

> 🎯 **新手必须记住**：`;`（分号）不能丢。
> 99% 的编译错误第一件事就是检查分号。

### 编译并运行

**方式 A：命令行（推荐先学会）**

打开 PowerShell，`cd` 到文件所在目录，然后：

```powershell
g++ -std=c++17 -O2 -Wall main.cpp -o main.exe
./main.exe
```

逐段解释：

| 部分 | 含义 |
|---|---|
| `g++` | 调用编译器 |
| `-std=c++17` | 用 C++17 标准（竞赛主流） |
| `-O2` | 开启优化，**交题时必开**；本地调试建议用 `-O0` 方便看变量 |
| `-Wall` | **打开所有警告**。新手 90% 的隐藏 bug 靠它发现 |
| `main.cpp` | 源文件 |
| `-o main.exe` | 输出的可执行文件名（`-o` = output） |

**方式 B：VS Code 一键编译**

本手册自带了 `.vscode/` 配置。
**用 VS Code 打开 `studyself` 这个文件夹**，配置就会自动生效：

| 快捷键 | 作用 |
|---|---|
| `Ctrl + Shift + B` | 编译当前文件 |
| `F5` | 编译 + 启动调试 |
| `Ctrl + F5` | 编译 + 直接运行（不调试） |

> ⚠️ 如果报错说找不到 `g++.exe`，
> 打开 `.vscode/tasks.json`，把
> `"command": "C:\\mingw64\\bin\\g++.exe"` 改成你自己的路径。

## 1.5　竞赛程序的「标准骨架」

入门之后，你会反复看到这个结构，**建议背下来**：

```cpp
#include <bits/stdc++.h>   // 万用头文件，竞赛专用
using namespace std;

using ll = long long;
const int MOD = 1e9 + 7;
const int INF = 0x3f3f3f3f;

void solve() {
    // 每个测试点的主要逻辑写这里
}

int main() {
    ios::sync_with_stdio(false);   // 加速 cin/cout
    cin.tie(nullptr);

    int T = 1;
    // cin >> T;                   // ← 多组数据时取消注释
    while (T--) solve();

    return 0;
}
```

**几个细节说明：**

```cpp
#include <bits/stdc++.h>
```
这是 GCC 提供的**万用头文件**，把所有标准库一次性全引入。
**竞赛专用**（方便），但**工程上不推荐**（编译慢、不可移植）。
其他编译器（如 MSVC）不认识它——所以别在 Visual Studio 里用它。

```cpp
ios::sync_with_stdio(false);
cin.tie(nullptr);
```
C++ 的 `cin/cout` 默认要和 C 的 `scanf/printf` 保持同步，
这拖慢了速度。这两行**关掉同步**，让 `cin/cout` 快到和 `scanf` 差不多。

> ⚠️ 关掉之后**不要混用** `cin` 和 `scanf`，否则会出乱子。

```cpp
const int INF = 0x3f3f3f3f;
```
竞赛里「无穷大」的常用写法，值是 `1061109567`（约 `1.06e9`）。
用它是因为：**两个 INF 相加不会溢出** `int`
（而 `INT_MAX + INT_MAX` 会直接溢出成负数）。

## 1.6　输入输出：竞赛的入口和出口

竞赛题的判题流程是：

```
测试数据 ──(标准输入 stdin)──► 你的程序 ──(标准输出 stdout)──► 判题机比对
```

所以你的程序**不需要**打印「请输入 n」这种提示语！**打印了就是错误答案**。

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int a, b;
    cin >> a >> b;              // 读入两个整数
    cout << a + b << '\n';      // 输出它们的和
    return 0;
}
```

```cpp
cin >> a >> b;
```
`cin` = character input。`>>` 是**流提取运算符**，
它**自动跳过空白字符**（空格、换行、Tab），所以 `"3 5"` 和 `"3\n5"` 都能正确读入。

```cpp
cout << a + b << '\n';
```

**关于换行：`endl` 还是 `'\n'`？**

| 写法 | 含义 | 速度 |
|---|---|---|
| `endl` | 输出换行 **并强制刷新缓冲区** | 慢 |
| `'\n'` | 只输出一个换行符 | **快** |

输出量大的题（比如要输出 1e6 个数），
用 `endl` 会**超时**，用 `'\n'` 才能过。**从今天起养成写 `'\n'` 的习惯。**

## 1.7　调试：程序错了怎么办

### 方法一：打印中间变量（最常用，别看不起它）

```cpp
cout << "debug: i = " << i << ", sum = " << sum << '\n';
```

关键技巧：**加特殊标记**方便定位，而且**调完一定要删掉**
（忘了删 → 输出多余内容 → 判成错误答案，这个错误极易发生）。

### 方法二：单步调试

在 VS Code 里：
1. 在行号左边**点一下**，出现红点（断点）
2. 按 `F5` 启动调试
3. 程序停在断点处，左侧可以看**所有变量的值**
4. `F10` 单步跳过，`F11` 单步进入，`F5` 继续运行

### 方法三：小黄鸭调试法

对着代码，一行一行地**读给自己听**：
「这里 i 从 0 开始…所以 a[0] 是第一个元素…」

**80% 的 bug 会在你读第二遍的时候自己现形。**

### 方法四：对拍（进阶但极其有用）

造一个暴力程序（慢但一定对）+ 一个随机数据生成器，
不断比较两个程序的输出，直到找出反例。第 13 章会讲具体写法。

## 1.8　报错急救包

### 编译期报错

| 报错信息 | 原因 | 怎么修 |
|---|---|---|
| `'xxx' was not declared in this scope` | 变量名写错 / 忘了声明 / 忘了 `#include` | 检查拼写；确认头文件 |
| `expected ';' before 'xxx'` | **上一行少了分号** | 去看**上一行**的末尾 |
| `expected '}' at end of input` | 大括号没配对 | 在 VS Code 里点括号，会自动高亮配对 |
| `'cin' has not been declared` | 忘了 `#include <iostream>` 或 `using namespace std;` | 用 `bits/stdc++.h` 一劳永逸 |
| `redefinition of 'int x'` | 同一个变量定义了两次 | 改名字或删一个 |
| `ld returned 1 exit status` | 链接失败：通常是有 `main` 没写全，**或上一个 `main.exe` 还在运行** | 关掉运行中的窗口，重新编译 |
| `'g++' 不是内部或外部命令` | Path 没配好 / 没重开终端 | 重开终端；检查 `C:\mingw64\bin` 是否存在 |

### 运行期问题

| 现象 | 原因 | 怎么修 |
|---|---|---|
| 程序没输出就结束 | 逻辑写错，或提前 `return` | 加打印定位 |
| 输出 `-1` 或奇怪的负数 | **整数溢出** | 换成 `long long` |
| 输出一堆乱码 | 源文件编码不是 UTF-8 | VS Code 右下角点编码 → 「通过编码保存」 → **UTF-8** |
| 答案差一个 | 下标从 0 还是 1 搞混了 | 统一约定，全程一致 |
| 数组越界，程序直接崩 | 访问了 `a[n]`（合法下标只有 `0..n-1`） | 数组**开大一点** |

> 🎯 **一个救命习惯**：全局数组**一律开大 5~10 个**。
> 写 `int a[100005];` 而不是 `int a[100000];`。
> 边界溢出是竞赛里最难查的错误之一。

## 1.9　本章练习

1. 编译运行 `Hello, World!`，看到输出。
2. 读入两个整数，输出它们的**和、差、积、整除商**。
3. 读入一个整数 n，输出 `1 + 2 + ... + n`。
4. **故意**删掉一个分号，观察报错信息，再改回来。
5. **故意**把数组开成 `a[10]` 然后访问 `a[100]`，

   说出其中每个字段的作用。
