## 13.2　卡常技巧（程序跑太慢时看）

**先确认三件事，再考虑卡常：**

1. **复杂度对吗？** 复杂度错了，卡常没用。先回去换算法。
2. **真的超时了吗？** 造「极限数据」测一下（`n` 取最大值）。
3. **有没有明显的浪费？** 比如 `endl`、忘了关同步。

**「免费提速」清单（按性价比排序）**：

| 技巧 | 提速 |
|---|---|
| `cout << '\n'` 代替 `endl` | ★★★★★ |
| `ios::sync_with_stdio(false); cin.tie(nullptr);` | ★★★★★ |
| 一维 `vector` 代替二维（连续内存、缓存友好） | ★★★ |
| 数组开全局（不用 `vector`，避免堆分配） | ★★★ |
| 矩阵乘法循环顺序改成 `i, k, j` | ★★★ |
| `scanf/printf` 代替 `cin/cout` | ★★★ |
| `reserve()` 预分配空间 | ★★ |
| 提前 `continue`（跳过无用分支） | ★★ |
| 用 `int` 代替 `long long`（确定不溢出时） | ★★ |
| 减少递归（改成迭代） | ★★ |

**快读模板（读入量极大时用，如 `1e7` 个数）**：

```cpp
inline int read() {
    int x = 0, f = 1;
    char ch = getchar();
    while (ch < '0' || ch > '9') {
        if (ch == '-') f = -1;
        ch = getchar();
    }
    while (ch >= '0' && ch <= '9') {
        x = x * 10 + ch - '0';
        ch = getchar();
    }
    return x * f;
}

// 用法：int n = read();
```

> 💡 用了 `read()` 之后，`main` 里**不要再混用** `cin`，
> 因为 `getchar` 和 `cin` 的缓冲区会打架。

**编译优化指令（放在文件最上方，谨慎用）**：

```cpp
#pragma GCC optimize("Ofast", "unroll-loops")
#pragma GCC target("avx2")
```

> ⚠️ **有些 OJ 会禁用 `#pragma`**，交之前先确认。
> 而且开了 `Ofast` 可能让**浮点精度变差**。

## 13.3　对拍（验证算法的终极武器）

### 13.3.1 什么是对拍

**问题**：你写了个「聪明算法」，过了样例，但**不确定对不对**
（尤其是贪心、剪枝、哈希这类「可能错」的算法）。

**对拍**：写一个「**慢但一定对**」的暴力程序，随机造数据，
让两个程序跑同一份输入，比对输出。一旦不同，就把这组数据留下来分析。

```
  gen.exe  →  data.in  ──┬──►  your.exe   →  your.out
（随机造数据）            └──►  brute.exe  →  brute.out
                                            ↓
                                      比对两个 out，不同就报错
```

### 13.3.2 三个程序

**① 数据生成器 `gen.cpp`**

```cpp
#include <bits/stdc++.h>
using namespace std;

// 用「当前时间」做随机种子，保证每次运行数据都不同
mt19937_64 rng(chrono::steady_clock::now().time_since_epoch().count());

long long rnd(long long l, long long r) {
    return uniform_int_distribution<long long>(l, r)(rng);
}

int main() {
    int n = (int)rnd(1, 10);             // 小数据容易暴露问题
    int m = (int)rnd(1, 10);
    cout << n << ' ' << m << '\n';

    for (int i = 0; i < n; i++) {
        cout << rnd(1, 20) << " \n"[i == n - 1];
    }
    return 0;
}
```

> 🎯 **造数据的关键技巧**：
> 1. **先从小数据开始**（`n ≤ 10`）——小数据最容易暴露边界 bug
> 2. 再逐渐加大（`n ≤ 100`、`n ≤ 1000`）
> 3. **构造特殊数据**：全相等、全递增、全递减、全是 0、只有一个元素……
> 4. **一定要覆盖边界**：`n = 1`、`n = 2`、最大值

**② 暴力程序 `brute.cpp`**

枚举所有可能，慢但一定对。比如「求最大子段和」的暴力：

```cpp
// O(n^3) 暴力：枚举所有子段
long long ans = LLONG_MIN;
for (int l = 0; l < n; l++) {
    for (int r = l; r < n; r++) {
        long long sum = 0;
        for (int k = l; k <= r; k++) sum += a[k];
        ans = max(ans, sum);
    }
}
```

**③ 比对脚本 `run.bat`（Windows）**

```bat
@echo off
for /L %%i in (1,1,1000) do (
    gen.exe > data.in
    your.exe < data.in > your.out
    brute.exe < data.in > brute.out
    fc your.out brute.out > nul
    if errorlevel 1 (
        echo ===== 发现反例！=====
        echo --- 输入数据 ---
        type data.in
        echo --- 你的输出 ---
        type your.out
        echo --- 正确答案 ---
        type brute.out
        pause
        exit /b
    )
)
echo 1000 组测试全部通过！
pause
```

**Linux / macOS 用这个 `run.sh`**：

```bash
#!/bin/bash
for i in $(seq 1 1000); do
    ./gen > data.in
    ./your < data.in > your.out
    ./brute < data.in > brute.out
    if ! diff -q your.out brute.out > /dev/null; then
        echo "===== 发现反例！====="
        cat data.in
        echo "--- 你的输出 ---"; cat your.out
        echo "--- 正确答案 ---"; cat brute.out
        exit 1
    fi
done
echo "1000 组测试全部通过！"
```

### 13.3.3 对拍最常用的四个场景

| 场景 | 为什么需要对拍 |
|---|---|
| **贪心** | 贪心不一定是错的，但**你没法确定它对** |

> 很多看起来「玄学错」的题，对拍 30 秒就能定位。

## 13.4　随机数生成

### 13.4.1 三种随机方式

```cpp
// ① rand()：老式，范围小（RAND_MAX 通常 32767），**不推荐**
srand(time(0));
int x = rand() % 100;

// ② mt19937：C++11 梅森旋转，推荐
mt19937 rng(chrono::steady_clock::now().time_since_epoch().count());
int x = uniform_int_distribution<int>(1, 100)(rng);

// ③ mt19937_64：64 位版本（哈希 base、随机种子）
mt19937_64 rng64(chrono::steady_clock::now().time_since_epoch().count());
long long y = rng64();
```

### 13.4.2 常用封装（造数据必备）

```cpp
mt19937_64 rng(chrono::steady_clock::now().time_since_epoch().count());

// [l, r] 的随机整数
long long rnd(long long l, long long r) {
    return uniform_int_distribution<long long>(l, r)(rng);
}

// [l, r] 的随机浮点
double rndDouble(double l, double r) {
    return uniform_real_distribution<double>(l, r)(rng);
}

// 随机打乱数组（洗牌）
template <class T>
void shuffleVec(vector<T> &v) {
    std::shuffle(v.begin(), v.end(), rng);
}

// 随机生成一棵树（n 个节点，父亲 p_i < i）
vector<int> randomTree(int n) {
    vector<int> p(n + 1);
    for (int i = 2; i <= n; i++) p[i] = (int)rnd(1, i - 1);
    return p;
}

// 随机生成一个排列
vector<int> randomPermutation(int n) {
    vector<int> a(n);
    iota(a.begin(), a.end(), 1);
    shuffleVec(a);
    return a;
}
```

> 🎯 **「随机化」本身也是一种算法手段**：
> - **随机化快排**（防被卡）
> - **随机化哈希**（`base` 随机，防构造碰撞）
> - **随机化贪心**（多跑几次取最优）
> - **Miller-Rabin**（随机选基，本仓库用的是固定基保证确定性）

## 13.5　`__int128` 输入输出

```cpp
using i128 = __int128_t;

// 读入
i128 readI128() {
    i128 x = 0;
    int f = 1;
    char ch = getchar();
    while (ch < '0' || ch > '9') {
        if (ch == '-') f = -1;
        ch = getchar();
    }
    while (ch >= '0' && ch <= '9') {
        x = x * 10 + (ch - '0');
        ch = getchar();
    }
    return x * f;
}

// 输出
void printI128(i128 x) {
    if (x < 0) { putchar('-'); x = -x; }
    if (x > 9) printI128(x / 10);
    putchar('0' + (int)(x % 10));
}
```

**最常用的用法**：只在乘法里用一下，马上取模变回 `long long`：

```cpp
const long long MOD = 1e18 + 3;          // 模数接近 1e18
long long a = 1e18, b = 1e18;
long long c = (long long)((i128)a * b % MOD);   // ← 防溢出乘法
```

> ⚠️ **`__int128` 是 GCC 扩展**，MSVC（Visual Studio）不支持。
> 但所有竞赛 OJ 都用 GCC，所以放心用。

### 13.6.2 提交前的检查清单（很重要）

| 检查项 | 说明 |
|---|---|
| ✅ **数据范围对了吗** | `n` 最大是多少？数组开够了吗？ |
| ✅ **类型够大吗** | 会溢出吗？该用 `long long` 吗？ |
| ✅ **多组数据清空了吗** | 全局数组、`vector`、`set`、`Trie` 都要清 |
| ✅ **调试输出删了吗** | 留着 `cout << "debug"` 就是 `WA` |
| ✅ **取模处理对吗** | 减法有没有 `+MOD`？ |
| ✅ **边界情况** | `n = 1`、空输入、全相等、无解 |
| ✅ **输出格式** | 换行、空格、`-1`、保留几位小数 |
| ✅ **复杂度** | 极限数据大概跑多久？ |

**这张表能挡掉 80% 的「莫名其妙 WA」。**

### 13.6.3 卡住时的策略

**不要在一道题上死磕超过 20 分钟。** 按这个顺序试：

1. **先写暴力拿部分分**（保底）
2. 试着**优化暴力**（加记忆化、剪枝、数据结构）
3. 换个**角度重想**（换状态定义、换个变量）
4. **手玩小数据**（`n = 1, 2, 3` 手算答案，找规律）
5. **看数据范围反推算法**（[第 03 章 3.2 节](03-复杂度与基础算法.md) 的表）
6. 去**做别的题**（转移注意力，回来常有新灵感）
